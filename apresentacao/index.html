03 · Construção · variáveis e tipos

Um dado do mundo
vira um objeto.

Uma variável é um nome para um valor guardado. Um objeto agrupa vários valores que descrevem a mesma coisa.

  • string — texto, sempre entre aspas
  • number — número, sem aspas

Só isso por enquanto. Dois tipos resolvem a nossa aula inteira.

vagas.js
// uma variável guarda UM valor
const meuNivel = "junior";

// um objeto guarda VÁRIOS valores
// que descrevem a mesma coisa
const vaga = {
  titulo:  "Dev Front-End Junior",
  empresa: "Orla Digital",
  nivel:   "junior",
  salario: 2200
};

console.log(vaga.salario);  // 2200
4:55 – 6:10

"Cada campo tem um tipo. Repara: 2400 sem aspas é número — dá pra comparar e somar. Se eu escrevesse '2400' com aspas, viraria texto, e texto não se compara por tamanho do jeito que a gente quer. Esse é o erro número um de quem está começando."

Se der tempo, rode node vagas.js ao vivo. Código executando na frente da banca vale muito em Domínio técnico (20).

03 · Construção · estruturas de dados

Muitos objetos
viram um array.

Essa é a estrutura de dados mais comum de toda a programação web: uma lista de objetos iguais na forma, diferentes no conteúdo.

Escolher a estrutura certa é meio caminho: com um array, o computador consegue percorrer, filtrar e ordenar. Com 120 variáveis soltas, não conseguiria nada.

vagas.js
// um array é uma lista de coisas
const vagas = [ vaga1, vaga2, vaga3, ... ];

// quantas vagas tem na lista?
console.log(vagas.length);       // 120

// a PRIMEIRA vaga da lista
console.log(vagas[0].titulo);    // "Dev Front-End Estagio"

A contagem começa no zero. A primeira vaga é vagas[0], não vagas[1].

03 · Construção · estruturas condicionais

A pergunta que
o código faz.

Condicional é como o programa decide. Ela só responde true ou false.

  • === é igual a
  • >= é maior ou igual a
  • && exige as duas coisas
vagas.js
const vaga = vagas[0];

if (vaga.nivel === "junior") {  console.log("Essa serve pra mim!");
} else {
  console.log("Essa nao.");
}

// exigindo as duas coisas:
if (vaga.nivel === "junior" &&
    vaga.salario >= 2000) { ... }
7:10 – 8:25

"O if faz uma pergunta que só tem duas respostas: sim ou não. E o && quer as DUAS coisas ao mesmo tempo — júnior e pagando 2000 ou mais. Se fosse ||, bastaria uma das duas."

Leia o if em voz alta como português: “se o nível da vaga for igual a junior”. Ler código em voz alta é o hábito que destrava iniciante.

03 · Construção · estruturas de repetição

Uma vez escrito,
120 vezes executado.

A repetição é o que faz valer a pena. O trabalho de escrever uma regra é pago pelo computador aplicando ela em toda a lista.

Se a lista virar 10.000 vagas amanhã, este código não muda uma linha.

vagas.js
// a minha lista, ainda vazia
const minhasVagas = [];

for (let i = 0; i < vagas.length; i++) {  const vaga = vagas[i];

  if (vaga.nivel === "junior" &&
      vaga.salario >= 2000) {
    minhasVagas.push(vaga);
  }
}

console.log(minhasVagas.length);  // 24

i começa em 0, sobe de 1 em 1, e para quando acaba a lista.

8:25 – 9:40

"Três partes: onde começa, até quando vai, de quanto em quanto anda. De 120 sobraram 24. A gente saiu de uma lista impossível para uma lista possível."

Se a banca perguntar sobre while: "uso for quando sei quantas vezes vou repetir e while quando dependo de uma condição — aqui eu sei o tamanho da lista".

03 · Construção · funções

Dar nome
a uma ideia.

Função é um pedaço de código com nome. Você escreve uma vez e usa quantas vezes quiser.

Repare: é o mesmo código que a gente já escreveu. A diferença é que agora o nível vem de fora — então serve para júnior, para estágio, para qualquer um.

vagas.js
function buscarVagas(vagas, nivel) {
  const encontradas = [];

  for (let i = 0; i < vagas.length; i++) {
    if (vagas[i].nivel === nivel) {
      encontradas.push(vagas[i]);
    }
  }
  return encontradas;
}

buscarVagas(vagas, "junior");   // 34 vagas  buscarVagas(vagas, "estagio");  // 35 vagas

04 · Abertura de projetos

Código solto
não é projeto.

Um arquivo na área de trabalho chamado teste2.js não é entregável. Projeto tem estrutura, identidade e instruções.

É o que permite outra pessoa — ou você daqui a três meses — abrir e entender em cinco minutos.

mural-vagas/
mural-vagas/
├── src/
│   ├── vagas.js       // a lógica
│   └── dados.json     // os dados
├── README.md       // o que é e como rodar
├── .gitignore       // o que NÃO versionar
└── package.json     // identidade do projeto

O README é a porta de entrada. Um projeto sem README é uma casa sem placa.

05 · Versionamento · comandos

Um commit é
um save point.

Todo commit guarda o que mudou, quem mudou, quando e por quê. É o “por quê” que faz a diferença.

Mensagem ruim: "ajustes"
Mensagem boa: "feat: filtra vagas por nível júnior"

➜ git status # o que mudou?
➜ git add src/vagas.js # pra prateleira
➜ git commit -m "feat: filtra vagas por nível"
➜ git log --oneline # ver o histórico

a3f9c21 feat: filtra vagas por nível
7b2e004 feat: carrega lista de vagas
1c8d5fa chore: abre o projeto

Esse histórico é a prova do seu raciocínio — e é o que um recrutador lê no seu GitHub.

Apoio · arguição (10 min) · não apresentar

“Como você adapta isso para quem nunca viu um computador?”

Primeiro encontro sem código: o algoritmo é escrito no papel, em português, em duplas. O código só entra quando a lógica já está resolvida. Pareamento entre quem tem mais e menos facilidade.

“E se o aluno não tiver notebook?”

Todo o material roda em navegador com editor online, e o repositório fica no GitHub — acessível de qualquer máquina do laboratório. Nada depende de instalação local.

“Por que PBL e não aula expositiva?”

Porque o edital exige e porque funciona: o aluno retém o que usou para resolver um problema que ele reconhece. O conteúdo aparece quando é necessário para avançar, não antes.

“Como você avalia quem não entrega?”

Avaliação é formativa: eu vejo o progresso pelos commits, não só pela entrega final. Aluno sem commit em uma semana é sinalizado e recebe acompanhamento antes de virar reprovação.

“Git não é avançado demais para a Trilha Básica?”

Ao contrário — quanto mais cedo, menos vício. Ensino só quatro comandos e um modelo mental de três caixas. Branch e PR entram na semana seguinte, com o squad já formado.

“Como isso ocupa 40 horas?”

Este é o encontro de abertura. O mesmo problema gerador atravessa o módulo: refinamos o algoritmo, adicionamos novas regras de filtro, o dataset cresce, e o repositório vira o Projeto Integrador da trilha.

“Qual a diferença entre let, const e var?”

const não permite reatribuição; let permite e tem escopo de bloco; var tem escopo de função e é legado — ensino const por padrão e let quando o valor muda.

“Por que === e não ==?”

== converte tipos antes de comparar e gera surpresas — "2" == 2 é verdadeiro. === compara valor e tipo. Ensino só === desde o primeiro dia.

“Por que não ensinar filter direto?”

Porque filter esconde o que está acontecendo. Com o for o aluno vê o índice andando e entende o mecanismo. Os métodos de array entram no encontro 06, apresentados como “o mesmo for, escrito curto”.

“E se der conflito no merge?”

É conteúdo previsto: provoco um conflito de propósito no laboratório, para o aluno ver os marcadores, escolher o que fica e concluir o merge. Conflito assusta uma vez só.

“Como lida com o aluno muito adiantado?”

Ele vira revisor: recebe os PRs do squad para comentar antes de mim. Aprofunda sem atropelar a turma e desenvolve a competência de revisão por pares.

“Qual estrutura de dados além de array?”

Na trilha básica: array, objeto e array de objetos. Menciono Map e Set como próximo passo, ligando ao módulo de POO & TypeScript que vem em seguida.
